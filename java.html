1. Java Basics

1.1 Platform Independence, JVM, JRE and JIT

  • Platform independence: Java code is compiled to bytecode, which is machine independent. The same bytecode runs on any OS that has a JVM, so Java does not depend on the operating system it runs on.
  • JVM (Java Virtual Machine): An abstract specification that runs Java bytecode. Its implementations (Oracle, OpenJDK and others) are platform dependent.
  • JRE (Java Runtime Environment): The concrete implementation of the JVM, shipped with the libraries and files the JVM needs at runtime.
  • JIT (Just-In-Time) compiler: Part of the JRE. At runtime it compiles frequently executed bytecode sequences into native machine code to improve performance.

1.2 Class Loaders

A class loader is a JVM subsystem that loads .class files. The program's main class is loaded first by the class loader.

Class loader Role
BootstrapLoads core classes such as java.lang.String, java.lang.Object, java.util.ArrayList. Implemented in native code. In Java 8 it loaded rt.jar. Parent of the Platform loader.
Platform / ExtensionChild of Bootstrap, parent of System. Loads non-core Java SE modules such as java.sql. Replaced the Extension loader in Java 9+; in Java 8 it loaded jars from jre/lib/ext.
System / ApplicationLoads the application's own classes and dependencies from the classpath (-cp, -classpath, CLASSPATH). ClassLoader.getSystemClassLoader() returns it.

Custom class loaders can be created by extending ClassLoader or URLClassLoader. This is common in application servers, plugin systems and frameworks that load or isolate classes dynamically.

1.4 Static Members

  • Static variables and methods belong to the class, not to any object. They are shared by all objects of the class and stored in the class area.
  • Static variables get memory once, at class loading. A static method can read and change static data.
  • Example: the college name is common to all students, so it is declared static.

Restrictions on static methods:

  1. A static method cannot use non-static data members or call non-static methods directly.
  2. this and super cannot be used in a static context.
  3. Static methods cannot be overridden.
  • A static block runs at class-loading time, before main.
  • Why is main static? The JVM can call a static method without creating an object. If main were non-static, the JVM would first have to create an object, which costs extra memory.

1.5 The synchronized Modifier

synchronized is a non-access modifier. It allows only one thread at a time to access a method (or block). See Multithreading.

1.6 String Immutability

  • A String object cannot be changed after creation. Any "modification" creates a new String object, and the old one is left unchanged.
  • Because strings are immutable, they can be shared safely between threads. 
String a = "a";
a = "ty";   // a new object is created; the old "a" is unchanged
  • To change text often, use StringBuilder or StringBuffer, which are mutable.
  • StringBuilder is faster and should be preferred. StringBuffer is thread-safe and should be used only when thread safety is needed.

1.7 Wrapper Classes and Autoboxing

  • Autoboxing: automatic conversion of a primitive into its wrapper type (for example int to Integer). The reverse is unboxing.
  • Wrapper classes are used where objects are required, such as collections and generics, and they provide utility methods.
  • All standard primitive wrapper classes (Integer, Long, Double, Boolean and others) are immutable. Their value cannot be changed after creation.
  • Note: AtomicInteger is mutable and thread-safe. It is not an immutable wrapper.

1.8 String Pool and Comparison

  • The String pool is a pool of String objects kept in the heap. It reduces the number of String objects created.
  • Ways to create a String:
    • new String("Joey"): always creates a new object, outside the pool.
    • Literal or constant expression, such as "Joey" or "Joe" + "y": uses the pool. If the string already exists in the pool, the existing reference is returned. Otherwise a new object is created and added to the pool.
  • == compares references (memory addresses), and equals() compares content.
  • intern() returns the pooled instance for a string. 
String s1 = "Rachel";
String s2 = "Rachel";
String s3 = new String("Rachel");
String s4 = new String("Rachel").intern();

s1 == s2;  // true  (same pooled object)
s1 == s3;  // false (new object)
s1 == s4;  // true  (intern returns the pooled object)

1.9 Object Creation and Object Lifecycle

  • In Java, an object lives in the heap. A local variable (which holds the reference) lives on the stack. Global (static or instance-level) data lives in the class area or heap, depending on the field.
  • The lifecycle of an object has these states: Created, In use, Invisible, Unreachable, Collected, Finalized, De-allocated.

1.10 Primitive Types, Casting and Immutable Classes

Type casting

Converting a value from one data type to another.

  • Widening (implicit, "casting up"): a smaller type is converted to a larger type automatically. It is safe because no data is lost. Chain: byte → short → int → long → float → double (char widens to int and larger types). 
    int x = 7;
long y = x;    // 7
float z = y;   // 7.0
  • Narrowing (explicit, "casting down"): a larger type is converted to a smaller one manually with a cast. The fractional part or extra high-order bits can be lost. If the cast is missing, the compiler reports an error. 
    double d = 166.66;
long l = (long) d;   // 166
int i = (int) l;     // 166

NaN comparison

Double.NaN == Double.NaN returns false. NaN ("not a number") is the result of invalid operations, and by the IEEE 754 standard it is not equal to any number, including itself. Use Double.isNaN(value) to test for it.

Immutable classes

To create an immutable class:

  1. Declare the class final, so it cannot be extended.
  2. Make all fields private.
  3. Do not provide setter methods.
  4. Make all fields final, so each is assigned only once.
  5. Initialize fields through the constructor, using a deep copy of any mutable input.
  6. In getters, return a copy of mutable objects rather than the actual reference.

Final collections

A final reference cannot be reassigned, but the object it points to can still be changed. A final List can be added to, but list = new ArrayList<>(); will not compile.

long count = testString.chars().filter(ch -> ch == '.').count();
long countCodePoints = testString.codePoints().filter(ch -> ch == '.').count();  // better with Unicode
// Apache Commons alternative: StringUtils.countMatches(testString, ".")

2. Exception Handling

2.1 Basics

An exception is an error event that occurs during execution and disrupts the normal flow of the program (for example, bad user input, hardware failure or network failure).

When an error occurs, an exception object is created and the JRE looks for a handler.

  • If a handler is found, the exception object is passed to it (this is called *catching* the exception).
  • If no handler is found, the exception is passed to the runtime environment and the JRE terminates the program.

2.2 Exception Handling Keywords

  • throw: explicitly creates and throws an exception object to halt normal processing.
  • throws: declared in a method signature when a checked exception is not handled inside the method, so callers know what may be thrown. Multiple exceptions can be listed, and it can be used on main().
  • try / catch: try starts the block that may throw; catch handles the exception. Multiple catch blocks are allowed, and blocks can be nested. The catch parameter must be of type Exception (or a subclass).
  • finally: optional, used only with try-catch. It always runs, whether or not an exception occurred. Use it to release resources (such as open files) that would otherwise stay open.

2.4 Exception Hierarchy

  • Throwable is the root. It has two children: Error and Exception.
  • Errors are outside the application's scope and cannot reasonably be recovered from, for example hardware failure, JVM crash or OutOfMemoryError.
  • Checked exceptions are anticipated problems that the program can recover from, for example FileNotFoundException. Catch them, show a helpful message and log them.
  • Runtime exceptions are caused by programming mistakes, for example reading an array element without checking the length first. Check the conditions in code rather than catching the exception.

2.5 Custom Exceptions

  • To create a custom exception, extend Exception (for a checked exception) or RuntimeException (for an unchecked one).
  • Provide a constructor that takes a message and passes it to super(message). Retrieve it later with getMessage().
  • Throw it with throw, usually inside a catch block that handles a more generic exception. 
public class ProductDataException extends Exception {
    public ProductDataException() { }
    public ProductDataException(String message) { super(message); }
}

public class ProductDB {
    public static Product getProduct(String code) throws ProductDataException {
        try {
            Product p = new Product();   // code that may throw an IOException
            return p;
        } catch (IOException e) {
            throw new ProductDataException("An IO error occurred.");
        }
    }
}

// Caller
try {
    Product p = ProductDB.getProduct(productCode);
} catch (ProductDataException e) {
    System.out.println(e.getMessage());
}

2.6 Exception Interview Points

  • Exception vs Error:
    • *Error* signals serious, abnormal conditions outside the application's control, such as memory, hardware or JVM errors. Applications should not try to handle them.
    • *Exception* is a condition in the code that the developer can handle and correct. Examples: ArithmeticException (divide by zero), NullPointerException, ArrayIndexOutOfBoundsException.
  • Checked exceptions are all exceptions except RuntimeException and its subclasses. The compiler checks that they are handled or declared. Examples: ClassNotFoundException, IllegalAccessException, NoSuchFieldException, EOFException.
  • Unchecked exceptions are RuntimeException and its subclasses. The compiler does not require handling them, but the programmer should prevent or handle them. Examples: ArithmeticException, ArrayIndexOutOfBoundsException, NullPointerException, NegativeArraySizeException.
  • throw vs throws:
throw throws
PurposeThrows an exception explicitlyDeclares the exceptions a method may throw
LocationInside the method bodyIn the method signature
Followed byAn exception instance (throw new Exception(...))Exception class names
CountOne exception per throwMultiple exception classes can be listed
  • Return values in try, catch and finally: if finally contains a return, it overrides the return values from try and catch. If finally has no return, the value from try (no exception) or catch (exception) is returned.
  • Multiple exceptions: one try can have several catch blocks. Put the more specific exception first, because a more generic catch placed earlier makes the specific one unreachable. In Java 7+, one catch can handle several types: catch (IOException | SQLException e).
  • Avoid catching Exception broadly. Catch specific exceptions. If an exception is not handled, it propagates up the call stack and terminates the thread or program.

2.7 Checked Exceptions and Custom Exceptions (Q&A)

  • Why does the compiler report an error for checked exceptions? Checked exceptions must be caught or declared in throws. This compile-time check reduces unhandled exceptions. The throws clause is part of a method's contract with its callers. An overriding method cannot throw a checked exception that the overridden method does not declare.
  • Example: the FileInputStream constructor throws FileNotFoundException, so the caller must declare it with throws or catch it.
  • Common checked exceptions: IOException, SQLException, ParseException.
  • Creating a custom exception:
    1. Extend java.lang.Exception (or RuntimeException for an unchecked exception).
    2. Provide a constructor that takes a message and passes it to super. 
class InvalidAgeException extends Exception {

}

class TestCustomException {

        if (age < 18) throw new InvalidAgeException("not valid");
        else System.out.println("welcome to vote");
    }
    public static void main(String[] args) {
        try {
            validate(13);
        } catch (Exception m) {
            System.out.println("Exception occured: " + m);

}

2.8 Try-with-resources (Java 7+)

  • Automatically closes resources such as files, database connections and sockets when the block ends. Before it existed, resources had to be closed in a finally block.
  • Only classes that implement AutoCloseable (or its subtype Closeable) can be used.
  • Multiple resources can be declared, separated by semicolons. They are closed in the reverse order of opening.
  • If both the block and close() throw exceptions, the close() exception is attached to the primary one as a suppressed exception. Retrieve it with getSuppressed(). 
try (FileInputStream in = new FileInputStream("a.txt");
     FileOutputStream out = new FileOutputStream("b.txt")) {
    // use the streams; both are closed automatically
}

3. Object-Oriented Programming (OOP)

3.1 Association, Aggregation and Composition

  • Association: a relationship between two separate classes through their objects. It can be one-to-one, one-to-many, many-to-one or many-to-many. Aggregation and composition are its two forms.
  • Aggregation: a special form of association.
    • Represents a *has-a* relationship.
    • Unidirectional. For example, a department has students, but a student does not "have" the department in the same sense.
    • Both objects can exist independently.
  • Composition: a restricted, stronger form of aggregation.
    • Represents a *part-of* relationship, and the parts depend on the whole. Example: a human and a heart. A heart does not exist separately from a human.

Relationhas-apart-of

3.2 Inheritance

  • A subclass inherits the properties and behavior of its superclass, and can extend them. Example: Car extends Vehicle.
  • Inheritance represents an *is-a* relationship and is one-directional.
  • Java uses two keywords for inheritance:
    • extends: between two classes, or between two interfaces.
    • implements: a class implements an interface.

Why Java does not support multiple class inheritance

Multiple inheritance is not supported in Java, to keep the language simpler. If class C extends both A and B, and A and B both define display(), the compiler cannot tell which method to call. This is the diamond problem.

class A { public void display() { System.out.println("class A display() method called"); } }
class B extends A { @Override public void display() { System.out.println("class B display() method called"); } }
class C extends A { @Override public void display() { System.out.println("class C display() method called"); } }

// Not allowed in Java:
public class D extends B, C { }   // compile-time error

Solution: default methods in interfaces (Java 8+)

Since Java 8, interfaces can have default methods. A class can implement two interfaces that have default methods with the same signature, as long as it overrides the method and chooses which one to call.

interface MyInterface1 {
    int num = 100;
    default void display() { System.out.println("display method of MyInterface1"); }
}
interface MyInterface2 {
    int num = 1000;
    default void display() { System.out.println("display method of MyInterface2"); }
}
public class InterfaceExample implements MyInterface1, MyInterface2 {
    @Override
    public void display() {
        MyInterface1.super.display();   // or MyInterface2.super.display()
    }
    public static void main(String[] args) {
        new InterfaceExample().display();
    }
}

If the override in InterfaceExample is removed, the compiler reports an error.

3.3 Polymorphism

Polymorphism lets one interface have multiple implementations: one action can be performed in different ways. The most common use is a parent-class reference that refers to a child-class object.

Type Also called Achieved by
Compile-time polymorphismStatic polymorphismMethod overloading (and operator overloading in some languages)
Run-time polymorphismDynamic method dispatchMethod overriding
  • Method overloading: several methods with the same name but different parameters (different number or types of arguments).
  • Method overriding: a subclass provides its own version of a superclass method. The method called is decided by the actual object at run time, even when it is referenced through a superclass variable. 
class Animal { void eat() { System.out.println("animal is eating..."); } }
class Dog extends Animal { @Override void eat() { System.out.println("dog is eating..."); } }

Animal a = new Dog();
a.eat();   // prints "dog is eating..."

3.4 Abstraction

Abstraction hides implementation details and shows only the functionality to the user. Java achieves it in two ways: abstract classes and interfaces.

Abstract class

  • Declared with the abstract keyword. It cannot be instantiated and must be extended.
  • Can have abstract and non-abstract methods, constructors and static methods.
  • Can have final methods, which subclasses cannot override.
  • Can have non-static, non-final fields, and public, protected and private concrete methods.
  • A class can extend only one class, abstract or not.

3.5 Encapsulation

  • Encapsulation wraps data (variables) and code (methods) into a single unit, and hides the object's internal details.
  • Make all data members private, and access them through public getters and setters. A JavaBean is a typical fully encapsulated class.
  • Setters give control over data. For example, a setter can reject id values that are not greater than 100, or negative values.
  • Providing only a getter makes a field read-only. Providing only a setter makes it write-only.
  • It is the main way to achieve data hiding, because other classes cannot access private data directly.

3.6 OOP Interview Points

Principles of OOP

  • Object: any entity with state and behavior, physical or logical (chair, pen, bike).
  • Class: a logical template for a group of objects.
  • Inheritance: a class acquires the properties and behavior of a parent class. It gives code reuse and supports run-time polymorphism.
  • Polymorphism: one task performed in different ways (for example, a cat "meows" and a dog "barks"). Achieved with overloading and overriding.
  • Abstraction: hiding internal details and showing only functionality (for example, a phone call). Achieved with abstract classes and interfaces.
  • Encapsulation: binding code and data into one unit (for example, a capsule). A JavaBean is a fully encapsulated class, because all its data members are private.

Encapsulation

  • Encapsulation protects an object's data and behavior from misuse by other objects. In Java it is done with access modifiers, getters and setters.
  • Even when a private variable is reached through a public getter or setter, the setter can validate or restrict changes, which is the value of encapsulation.

Protected vs default access

  • protected: visible within the same package, and in subclasses (even in other packages).
  • default (package-private): visible only within the same package.

Abstract class vs interface: when to use

  • Use an abstract class when related classes share state or partial behavior, or need constructors.
  • Use an interface to define a contract (a capability) that unrelated classes can implement. A class can implement many interfaces but extend only one class.
  • An interface where all methods are abstract is equivalent to a contract. Default and static methods let interfaces hold shared behavior without breaking existing implementations.

Static

  • A static variable belongs to the class and is shared by all objects.
  • A static method can access only static members directly.
  • A static block runs once, when the class is loaded.
  • A static method can be called from another class as ClassName.method(). A non-static method needs an object: obj.method().
  • A non-static method can call a static method of the same class directly.

Overloading vs overriding

Overriding rules:

  1. A method can be overridden only in a subclass, not in the same class.
  2. The overriding method cannot throw a broader checked exception than the overridden method. For example, if the original throws IOException, the override cannot throw Exception.
  3. The overriding method cannot reduce access. A public method cannot become protected or package-private. A protected method can become protected or public.
  4. private, static and final methods cannot be overridden.
  5. The return type must be the same as the overridden method's.

Overloading rules:

  1. Changing the method signature (name, number, order or types of parameters) is required.
  2. Changing only the return type does not overload a method. The compiler reports "duplicate method".

Default access of an abstract method: an abstract method with no access modifier has package access. It becomes visible outside the package only when a child class overrides it with public.

Final

  • Final variable: cannot be reassigned.
  • Final method: cannot be overridden.
  • Final class: cannot be subclassed. Examples in the standard library are java.lang.System and java.lang.String. This gives security and efficiency.

Other OOP points

  • Reflection: the ability to inspect and call classes, methods and fields at run time.
  • Object creation: an object is created with new, which allocates memory on the heap and runs a constructor.
  • Constructor: a special method with the class name and no return type. A default constructor is provided by the compiler when no constructor is declared.
  • this: refers to the current object. super: refers to the parent class, for example to call a parent constructor or method.
  • super() in a constructor: must be the first statement, so the parent part of the object is initialized before the child part.
  • Creating an object only when fields have certain values: do this in the constructor, or in a factory method that validates the values first and throws an exception if they are invalid.
  • Calling an abstract class: you cannot create an instance of an abstract class. You can create a reference of the abstract type that points to a subclass object: Animal a = new Dog();.
  • Parent reference, child object: when a.someMethod() is called and both classes override it, the method of the actual object (Dog) runs, not of the reference type (Animal). This is run-time polymorphism.
  • toString(): returns a string representation of an object. Override it so that printing an object shows useful data rather than its address.
  • equals() vs ==: == compares references. equals() compares content, if the class overrides it.
  • Multiple inheritance: not supported for classes because of the diamond problem. The workaround is to implement several interfaces, using default methods where needed.

SOLID principles

SOLID is five class-design principles:

  • Single Responsibility (SRP): a class should have only one reason to change. Example: a Vehicle class that prints details, calculates value and saves to the database should be split into three classes.
  • Open-Closed (OCP): classes should be open for extension but closed for modification. Instead of adding if (v instanceof Truck) branches in a calculator, let each subclass override calculateValue().
  • Liskov Substitution (LSP): a subclass must be usable wherever its base class is used, without breaking behavior. Classic counter-example: a Square that extends Rectangle and changes both dimensions when only one is set, so it cannot safely replace a Rectangle.
  • Interface Segregation (ISP): clients should not be forced to depend on methods they do not use. Prefer several small interfaces over one large one.
  • Dependency Inversion (DIP): depend on abstractions (interfaces) rather than concrete classes.

3.7 Additional OOP Points

  • JavaBean vs POJO:
    • A JavaBean follows conventions: getter and setter naming, a public no-argument constructor, and being serializable.
    • A POJO (plain old Java object) has no required interface, base class or annotation. It is any simple object, typically with private fields and getters and setters.
  • Marker interface: an interface with no methods, used to tag a class with metadata for the JVM or a framework. Examples: Serializable, Cloneable.
  • Can static methods be overridden? No. Static methods belong to the class, not to instances, so they are not polymorphic. A static method in a subclass with the same signature *hides* the parent's method rather than overriding it.

4. Multithreading

4.1 Overview

Multithreading allows two or more parts of a program to run concurrently, for maximum CPU utilization. Each part is a thread. Threads are lightweight processes that run within a process.

4.2 Creating Threads

There are two mechanisms:

  1. Extend the Thread class and override run().
  2. Implement the Runnable interface and override run().

In both cases, the thread begins in run(), and start() is called to start it. start() invokes run() on a new thread.

// 1. Extending Thread
class MultithreadingDemo extends Thread {
    public void run() {
        System.out.println("Thread " + Thread.currentThread().getId() + " is running");
    }
}
// Main: for 8 iterations -> new MultithreadingDemo().start();

// 2. Implementing Runnable
class MultithreadingDemo implements Runnable {
    public void run() {
        System.out.println("Thread " + Thread.currentThread().getId() + " is running");
    }
}
// Main: for 8 iterations -> new Thread(new MultithreadingDemo()).start();

Sample output (order may vary): Thread 8 is running, Thread 9 is running, ... Thread 15 is running.

4.3 Thread Class vs Runnable Interface

  1. Extending Thread uses up the class's only inheritance slot, because Java has no multiple class inheritance. Implementing Runnable leaves the class free to extend another base class.
  2. Extending Thread gives inbuilt thread methods such as yield() and interrupt(), which are not available in Runnable.

4.6 Thread Interview Points

  • Thread: the smallest, lightweight part of a process that runs concurrently with other threads of the same process. Each thread has its own path of execution, so an exception in one thread does not stop the others. All threads of a process share the same memory.
  • Multithreading: running multiple threads at the same time.
  • Starting a thread: create it by extending Thread or by implementing Runnable, then call start().

  • Multiprocessing: like multitasking, but more than one CPU is involved.
  • Parallel processing: using multiple CPUs in one computer system.

Monitor, wait, notify and notifyAll

  • Java synchronizes access through a monitor, which can be thought of as a box that holds one thread at a time. When a thread enters, the other threads must wait until it exits.
  • wait(): releases the monitor and makes the calling thread sleep until another thread calls notify() or notifyAll() on the same object.
  • notify(): wakes up one thread that called wait() on the same object.
  • notifyAll(): wakes up all threads that called wait() on the same object. The highest-priority thread runs first.
  • wait(), notify() and notifyAll() can only be called from within a synchronized method or block.

Why synchronized is used

When two or more threads need the same shared resource, synchronized makes sure only one thread uses it at a time. While a thread is inside a synchronized method, no other thread can call any other synchronized method on the same object. The other threads wait until the first one leaves.

CountDownLatch

  • Makes a task wait until other threads have finished. Example: the main task can start only after all required services have started.
  • You create it with a count, the number of threads to wait for. Each thread calls countDown() when ready. When the count reaches zero, the waiting task continues.

CyclicBarrier

  • A number of threads (called *parties*) wait for each other at a common point, the barrier. Each thread calls await(). When the last thread arrives, all threads continue.
  • It is similar to CountDownLatch, but a CyclicBarrier can be reused after it is tripped.
  • Used when several threads do separate sub-tasks and their results must be combined into a final output.

4.7 Thread Safety and Executors (Q&A)

  • Sharing data between threads: use synchronized, or a volatile variable for simple visibility of a value between threads.
  • volatile tells the JVM and threads to read the variable from main memory, not from a cached copy in the thread. It is used in concurrent programming. It provides visibility, not atomicity for compound operations (such as count++).
  • transient is different: it excludes a field from serialization (see Serialization).

ExecutorService

  • ExecutorService extends Executor with methods to manage and control task execution. It manages a pool of worker threads, and tasks are submitted to it.
  • It handles creation, management and reuse of threads.
  • Why use it instead of creating threads manually?
    • *Thread pooling:* threads are reused instead of created for each task.
    • *Resource efficiency:* less CPU and memory overhead.
    • *Scheduling:* tasks can run with a delay or periodically.
    • *Graceful shutdown:* provides methods to stop tasks cleanly.

4.8 Thread States, Methods and Types

  • Thread states (a thread is in exactly one state at a time):
    • NEW: created but not started.
    • RUNNABLE: executing in the JVM.
    • BLOCKED: waiting to acquire a monitor lock.
    • WAITING: waiting indefinitely for another thread to act.
    • TIMED_WAITING: waiting for a set time, or for another thread to act.
    • TERMINATED: has exited.
  • Useful Thread methods: getName(), getPriority(), isAlive(), join() (wait for the thread to finish), run() (the entry point), sleep() (pause for a period), start() (starts a new thread and calls run() on it).

  • sleep() does not stop processing for others. After the sleep, the thread moves to RUNNABLE and the scheduler decides when it runs.

  • User vs daemon threads: a user thread is created by the program, and the JVM waits for it before exiting. A daemon thread runs in the background, has low priority, provides support to other threads, and does not keep the JVM alive. It ends automatically when the user threads end.
  • Synchronized block vs synchronized method: a synchronized block is preferred. A synchronized method locks the whole object, so unrelated synchronized methods in the same class are blocked too. A block can lock only the object that needs protecting.

4.9 Concurrency Concepts

  • Process vs thread: a process is a running program with its own address space. Threads are sub-processes that share the address space of their process.
  • Context switching: saving the state of one thread or process so that it can resume later. It lets one CPU manage many threads.
  • Thread scheduler: allocates CPU time to threads and decides their order of execution.
  • Time slicing: the scheduler divides CPU time between active threads.
  • Thread priority: a hint to the scheduler, not a guarantee of order.
  • Deadlock: two or more threads wait for locks held by each other, so none can continue.
  • Livelock: threads keep changing state in response to each other, but make no progress (for example, endless loops).
  • Thread safety can be achieved with synchronized, volatile, or atomic wrapper classes such as AtomicInteger.

4.10 Deadlock

A deadlock occurs when thread A waits for a lock held by thread B, and thread B waits for a lock held by thread A. The synchronized keyword can cause this, because a thread blocks while it waits for the object's monitor.

Detecting a deadlock: take a thread dump of the application and look for threads in the BLOCKED state. Check which lock each one is waiting for, and which thread holds that lock. Each lock has a unique ID that makes this possible.

Avoiding deadlock (it cannot always be avoided completely):

  • Avoid nested locks. Holding one lock while acquiring another is the main cause.
  • Avoid unnecessary locks. Lock only what must be protected.
  • Use Thread.join() with a timeout, so a thread does not wait forever for another.

4.11 Synchronization Notes

  • Multithreading makes programs asynchronous. If one thread writes data while another reads it, the result can be inconsistent.
  • synchronized solves this. Once a thread is inside a synchronized method, no other thread can call any other synchronized method on the same object until it leaves.
  • volatile vs synchronized:
    • volatile guarantees visibility: the latest value is always read from main memory. Use it for shared flags or status variables.
    • synchronized guarantees atomicity and visibility by locking a block of code. Use it for compound actions or updates to shared mutable state.

4.12 Futures and Parallel Calls

  • Future (Java 5): submit a task asynchronously. get() blocks until the result arrives. There is no chaining or callbacks.
  • CompletableFuture (Java 8): non-blocking and asynchronous. Supports chaining (thenApply, thenAccept) and combining several tasks.
    • Without supplyAsync() or an executor, the work may still run on the same thread. Asynchronous does not mean parallel unless the task is submitted to a pool.

  • Runnable: no return value. Cannot throw checked exceptions.
  • Callable: returns a result. Can throw checked exceptions. Used with Future.

4.14 More Thread Interview Points

  • Daemon threads: setDaemon(true) must be called before start(), or IllegalThreadStateException is thrown. A child thread created by a daemon thread is also a daemon.
  • Lifecycle summary: a new thread is NEW. start() makes it RUNNABLE. The thread scheduler gives CPU time to RUNNABLE threads. Other states are WAITING, BLOCKED and TERMINATED. When no user threads remain, the JVM shuts down.
  • Calling run() directly runs it as a normal method in the current thread. Only start() creates a new thread.
  • Interrupting a thread: call interrupt() on it to break out of a sleep() or wait(). The thread receives an InterruptedException.
  • Ways to achieve thread safety: synchronized, atomic classes, explicit Lock implementations, volatile, immutable classes and thread-safe classes.
  • Static synchronization: a static synchronized method locks the class (the Class object). A regular synchronized method locks the instance. So only one thread can run a static synchronized method at a time, across all instances.
  • notify() vs notifyAll(): notify() wakes one waiting thread. notifyAll() wakes all of them.
  • Race condition: several threads access a shared resource at the same time, and the result depends on which one runs first. Synchronization prevents it.
  • Thread priority: a value from 1 (MIN_PRIORITY) to 10 (MAX_PRIORITY). The default (NORM_PRIORITY) is 5. The scheduler prefers higher-priority threads, but priority does not guarantee order. setPriority() throws IllegalArgumentException if the value is out of range.
  • ThreadLocal: a variable that has a separate value for each thread, the way an instance variable has one value per object.
  • Taking a thread dump: on Windows, press Ctrl+Break. On Linux, run kill -3 <pid>. Or use jstack <pid>, where the process ID comes from jps.
  • Thread.holdsLock(obj) returns true if the current thread holds the monitor lock on obj.

Thread pools and the Executor framework

  • A thread pool is a set of worker threads created at start-up. They are assigned tasks and returned to the pool when the task completes.
  • Why: creating a thread for each request is slow and resource-heavy, and a process can create only a limited number of threads.
  • From Java 5, the Executor framework creates pools: single-thread pool (one task at a time), fixed thread pool (a fixed number of threads), and cached thread pool (expands for many short-lived tasks).

Executor vs ExecutorService vs Executors

  • Executor is the parent interface. ExecutorService extends it.
  • Executor.execute() takes a Runnable and returns void. ExecutorService.submit() takes a Runnable or a Callable, and returns a Future with the result.
  • Executors is a factory class:

ExecutorService fixed = Executors.newFixedThreadPool(10);
ExecutorService scheduled = Executors.newScheduledThreadPool(10);

Deadlock example

Two threads take two locks in opposite orders, so each can end up holding one lock and waiting for the other forever.

String str1 = "Java";
String str2 = "UNIX";

// Thread 1: locks str1, then str2
synchronized (str1) {
    synchronized (str2) { System.out.println(str1 + str2); }
}

// Thread 2: locks str2, then str1  -> deadlock with Thread 1
synchronized (str2) {
    synchronized (str1) { System.out.println(str2 + str1); }
}

Fix: make every thread acquire the locks in the same order.

Volatile and atomic variables

  • volatile gives visibility: every read comes from main memory, not from a thread's cache. It does not make compound operations atomic.
  • The java.util.concurrent.atomic package provides atomic variables for single values: AtomicInteger, AtomicLong, AtomicBoolean and AtomicReference. Their methods include get(), set(), lazySet(), compareAndSet(expect, update), addAndGet(delta) and decrementAndGet(). Each operation cannot be interfered with by other threads.
  • In short: volatile ensures that a memory state is visible across threads. Atomic classes ensure that an operation on a variable is performed atomically.

Sharing data between threads

Share a common object, or use a concurrent data structure such as BlockingQueue. Use volatile, atomic classes, or synchronized to keep updates safe.

5. Memory Management

5.1 Overview

Java manages memory automatically. Objects are allocated and freed by the garbage collector (GC), so the application does not need its own memory management logic.

5.2 JVM Run-time Data Areas

Some areas are created by the JVM and exist until the JVM exits. Others are created per thread, when the thread is created, and destroyed when it exits.

  1. Class (Method) Area: stores per-class structures: the runtime constant pool, field and method data, and method code. In HotSpot it lives in Metaspace (native memory, not on the heap) since Java 8. Before Java 8 it was PermGen.
  2. Heap: the runtime area where objects are allocated. It is the main area managed by the GC and is divided into generations (young and old) in most collectors. Size is controlled with -Xms (initial) and -Xmx (maximum).
  3. Stack (per thread): stores frames for method calls, containing local variables, partial results and references to the constant pool. A new frame is created on each method invocation and destroyed when it completes. Size is controlled with -Xss. Exceeding it causes StackOverflowError.
  4. Program Counter (PC) Register (per thread): holds the address of the JVM instruction currently being executed.
  5. Native Method Stack (per thread): used by native (non-Java) methods.

5.3 Why Stack and Heap Are Designed This Way

  • The stack holds short-lived data: local variables and primitives. Each thread has its own stack.
  • The heap holds longer-lived data, such as objects that must be shared across methods and threads. It is shared by all threads.
  • The heap is much larger than the stack.
  • Because objects are on the heap, they can be passed easily between threads and code blocks.

5.4 Garbage Collection

  • The JVM decides when GC runs. It frees the programmer from manual deallocation.
  • System.gc() and Runtime.getRuntime().gc() request garbage collection, but the JVM makes the final decision, so GC is not guaranteed.

5.6 Memory Leaks

A memory leak occurs when objects are no longer needed by the application but are still reachable, so the GC cannot reclaim them.

Common causes: static collections, caches without eviction or TTL, listeners that are not removed, unclosed resources, and ThreadLocal values that are not cleaned up.

Relationship to OutOfMemoryError: Memory leak → objects stay reachable unnecessarily → heap usage keeps increasing → GC cannot reclaim enough memory → OutOfMemoryError.

A leak can eventually cause an OutOfMemoryError, but OutOfMemoryError can also occur without a leak, for example when the application genuinely needs more heap than is configured.

5.7 Troubleshooting a Memory Leak

  1. Monitor the heap. If the old generation keeps growing after GC, that is a strong warning sign.
  2. Take heap dumps. Useful JVM option: -XX:+HeapDumpOnOutOfMemoryError. Analyze the .hprof file with tools such as VisualVM or JProfiler.
  3. Watch GC behavior. If the post-GC baseline keeps increasing, investigate which objects are being retained.

5.8 PermGen vs Metaspace

  • Before JDK 8, class metadata (bytecode, names, JIT information) was stored in PermGen, which had a fixed size and did not grow automatically.
  • From JDK 8 onward PermGen was removed. Class metadata is stored in Metaspace, in native memory. It grows automatically by default, is garbage collected, and has no fixed size limit by default.

6. Serialization

Serialization converts an object into a stream of bytes, so it can be written to a file, sent over a network or stored in a database. De-serialization does the reverse: it rebuilds the object from the byte stream. The Java Serialization API provides both features. A class must implement java.io.Serializable to be eligible.

7.3 Functional Interfaces

A functional interface has exactly one abstract method. It can also have any number of default and static methods, and it can redeclare public java.lang.Object methods (such as toString or equals) without counting them as abstract.

@FunctionalInterface
public interface FunctionalInterface_one {
    void firstInt_method();
    @Override String toString();          // from Object, not counted
    @Override boolean equals(Object obj); // from Object, not counted
}
  • @FunctionalInterface is optional, but it makes the compiler reject an interface with more than one abstract method.
  • Many existing interfaces are functional, for example Comparable and Runnable.
  • Functional interfaces are implemented with lambda expressions.

7.4 Lambda Expressions

A lambda expression is an anonymous function: it has no name and does not belong to any class. It is written as (parameters) -> body.

Structure:

(Argument List) -> { expression; }
(Argument List) -> { statements; }

Examples:

() -> { System.out.println("Hello"); }     // no argument
(int a) -> { System.out.println(a); }      // one argument
(int a, int b) -> { return a + b; }        // two arguments, returns the sum
(a, b) -> a + b;                           // types inferred from context

Rules:

  • A lambda can have zero or more arguments.
  • Argument types can be omitted, because they are inferred from context. You cannot declare the type of some arguments and omit it for others.
  • With a single parameter whose type is inferred, the parentheses are optional.

Relation to functional interfaces: a lambda provides the implementation of a functional interface's single abstract method, so the method does not need to be written out again. This avoids bulky anonymous classes.

@FunctionalInterface
interface Drawable { void draw(); }

int width = 10;
Drawable d2 = () -> { System.out.println("Drawing " + width); };
d2.draw();   // Drawing 10

7.6 Default Methods

  • Default methods are interface methods with a body, marked with the default keyword.
  • Their purpose is backward compatibility. If new abstract methods were added to an interface that JDK already ships, every class implementing it would break. A default method can be added without breaking them.

Calling an interface default method from a class: use InterfaceName.super.method().

interface Vehicle {
    default void print() { System.out.println("I am a vehicle!"); }
}
class Car implements Vehicle {
    public void print() { Vehicle.super.print(); }
}

Calling a static interface method: use the interface name.

interface Vehicle {
    static void blowHorn() { System.out.println("Blowing horn!!!"); }
}
// Vehicle.blowHorn();

7.7 Method References

A method reference is a compact form of a lambda that only calls an existing method. The :: operator separates the class or object name from the method name.

  • Lambda num -> System.out.println(num) → method reference System.out::println.
  • A method reference can point to:
    • Static methods (e.g. Integer::parseInt)
    • Instance methods (e.g. System.out::println)
    • Constructors using new (e.g. TreeSet::new)

7.8 Type Inference

Type inference means the compiler determines the types of expressions (including lambda parameters and generic arguments) at compile time, by looking at each method call and its declaration.

7.9 Stream API

Stream vs Collection

A stream is a sequence of elements that can be pipelined through methods to produce a result. The Stream API is for processing streams of objects. It is not related to InputStream and OutputStream from java.io, which handle bytes.

Features of streams

  • A stream is not a data structure. It takes input from collections, arrays or I/O channels.
  • Streams do not change the original data source. They only produce a result.
  • Intermediate operations are lazy and return a stream, so they can be pipelined. A terminal operation ends the pipeline and returns the result.

Sequential vs parallel streams

  • collection.stream() creates a sequential stream. collection.parallelStream() creates a parallel one. A sequential stream can also be made parallel with parallel().
  • A sequential stream keeps elements in order.
  • A parallel stream splits work across cores, so order is not guaranteed. Use forEachOrdered() instead of forEach() to keep order. 
List<String> list = Arrays.asList("Hello ", "G", "E", "E", "K", "S!");
list.stream().forEach(System.out::print);            // Hello GEEKS!
list.parallelStream().forEach(System.out::print);    // order varies
list.parallelStream().forEachOrdered(System.out::print); // Hello GEEKS!

Does parallelStream improve performance? It depends on the workload.

  • Helps when: the data set is large (roughly tens of thousands of elements or more) and each element's work is CPU-heavy.
  • Hurts or does nothing when:
    • The collection is small. Splitting, scheduling and merging cost more than the work.
    • The work is I/O-bound (database calls, HTTP requests, file reads). Parallel streams use the shared ForkJoinPool.commonPool(), so blocking calls can starve other parallel tasks in the same JVM. This matters on servers.
    • The pipeline mutates shared state or has side effects, which causes race conditions or wrong results.

Stream operations

Intermediate operations (return a stream):

  • map: applies a function to each element. 
    List<Integer> square = Arrays.asList(2, 3, 4, 5).stream().map(x -> x * x).collect(Collectors.toList());
  • filter: keeps elements that match a Predicate. 
    List<String> result = Arrays.asList("Reflection", "Collection", "Stream")
        .stream().filter(s -> s.startsWith("S")).collect(Collectors.toList());
  • sorted: sorts the stream.

Stateless vs stateful intermediate operations:

  • Stateless: filter, map. Keep no state from previous elements.
  • Stateful: distinct, sorted. May depend on previous elements.

Terminal operations (end the pipeline):

  • collect: gathers results, for example into a list or set.
  • forEach: iterates over every element.
  • reduce: combines elements into one value, using a BinaryOperator. 
    int even = Arrays.asList(2, 3, 4, 5).stream()
        .filter(x -> x % 2 == 0)
        .reduce(0, (ans, i) -> ans + i);   // 6

Stream pipelining and collectors

  • Most stream operations return a stream, so calls can be chained. These are intermediate operations. collect() is usually the terminal operation that ends the pipeline.
  • Collectors combine the processed elements into the final result, such as a List, Set or String.

  • Static interface methods cannot be overridden in implementing classes.
  • Functional programming means writing code with expressions: functions are passed as arguments and used like values. Java 8 brought this style through lambdas.
  • Abstract class vs interface in Java 8: default methods make them look similar, but they still differ. An abstract class can have constructors, state and partial implementation. An interface is a pure contract with no constructors, and it is meant to provide full abstraction.

7.18 Map and FlatMap

  • map(): transforms each element one-to-one.
  • flatMap(): flattens nested structures, such as lists inside lists, into a single stream.

8. Java Collections

8.1 Collection Framework

The Collection framework is a unified architecture for storing and manipulating groups of objects. It has:

  1. Interfaces and their implementations (classes).
  2. Algorithms (utility methods such as sorting and searching).

It provides interfaces (Set, List, Queue, Deque) and classes (ArrayList, Vector, LinkedList, PriorityQueue, HashSet, LinkedHashSet, TreeSet). Maps (key/value pairs) are not collections in the strict sense, but they are fully integrated with the framework.

Iterable is the root interface of all collection classes. Collection extends it, so every collection is Iterable. It has one abstract method: Iterator<T> iterator().

8.10 ArrayList vs LinkedList

  • ArrayList is backed by a dynamically resizing array. Search by index is constant time. Add and remove in the middle are slower. Use it when reading is more frequent than adding or removing.
  • LinkedList is a doubly linked list. Add and remove are constant time. Use it when frequently inserting and removing.

8.11 Other Collection Notes

  • RandomAccess is a marker interface with no methods. ArrayList and Vector implement it, which means random access (for example, getting element 10 or element 17869) takes the same time.
  • Default initial capacity of ArrayList: 10.
  • Diamond operator (<>): lets the compiler infer the type arguments of a generic class, so the constructor does not need to repeat them.
  • Hash collisions: two different keys with the same hash value land in the same bucket. Java keeps both entries in that bucket, and equals() picks the right one. Two standard strategies are separate chaining and open addressing.
  • Internal working of HashMap: the key's hashCode() (after an internal hash function) gives the bucket index. Entries in the same bucket are compared with equals() to find the right value.
  • Custom keys in a HashMap: hashCode() and equals() must be consistent with each other. Make key objects immutable, so the hash code does not change after insertion. If a mutable key is used, its hashCode() must not depend on fields that can change. 
public class Account {
    private int accountNumber;
    private String holderName;   // can change at run time; not part of equality

    @Override
    public int hashCode() { return 31 + accountNumber; }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (obj == null || getClass() != obj.getClass()) return false;
        return accountNumber == ((Account) obj).accountNumber;
    }
}
  • Concurrent collections (java.util.concurrent): ConcurrentHashMap, CopyOnWriteArrayList and CopyOnWriteArraySet. They support concurrent reads and adjustable concurrency for updates. ConcurrentHashMap is thread-safe and does not allow null keys or values.
  • Collection vs Collections: Collection is the root interface of the framework. Collections is a utility class with static methods (for example sort, reverseOrder) that operate on collections.

8.13 Collection Interview Questions (Quick Answers)

  • ArrayList vs Vector: Vector is synchronized. ArrayList is not.
  • ArrayList vs LinkedList: see 8.10.
  • HashMap vs Hashtable: Hashtable is synchronized and does not allow nulls. HashMap is not synchronized and allows one null key.
  • HashSet vs TreeSet: HashSet has no order and is faster. TreeSet keeps elements sorted and does not allow nulls. HashSet performs better for add, remove, contains and size.
  • Iterator vs Enumeration: Enumeration is for legacy classes such as Vector. Iterator works on all collections, is fail-fast, and is slightly slower.
  • Iterator vs ListIterator: see the table in 8.8.
  • ArrayList vs HashMap: ArrayList is a list of values with index access. HashMap maps keys to values.
  • List, Set and Map: List is ordered with duplicates allowed. Set has unique elements. Map stores key/value pairs with unique keys.
  • Remove duplicates from an ArrayList: see 8.12.

8.14 More Collection Interview Points

  • for-each loop vs Iterator: a for-each loop cannot modify the collection during iteration, and doing so throws ConcurrentModificationException. An Iterator can remove elements safely (with iterator.remove()). Both give the same traversal performance. For nested loops, for-each is more readable.
  • How HashSet prevents duplicates: HashSet.add() calls HashMap.put() with the element as the key and a constant dummy value (PRESENT). If the key already exists, the old value is replaced, so the set never contains duplicates.
  • TreeSet: like HashSet but sorted in ascending order. It does not allow null elements. It is not synchronized, but it can be wrapped with Collections.synchronizedSortedSet(new TreeSet<>(...)).
  • hashCode and equals contract:
    1. If two objects are equal according to equals(), they must return the same hashCode().
    2. Two unequal objects may still have the same hash code. This is a *collision*. Example: with n % 10 as the hash function, 17 and 27 both map to 7, but they are not the same number.
  • ArrayList vs HashMap memory: an ArrayList stores only the values and uses internal indexes. A HashMap stores a key and a value for each entry, so it uses more memory.

8.15 HashMap and ConcurrentHashMap Internals (Q&A)

How HashMap works

  • A HashMap stores key-value pairs in an array of buckets.
  • put() computes the key's hash, applies an internal hash function, and calculates the bucket index. Keys that land in the same bucket are kept together. When a bucket has several entries, equals() identifies the exact key.
  • get() recalculates the bucket index and uses equals() to find the key.
  • When the number of entries exceeds capacity × loadFactor (default 16 × 0.75 = 12), the map resizes and rehashes its entries.
  • Average lookup and insertion are O(1).

Hash collisions

  • A collision occurs when two different keys produce the same bucket index. It cannot be avoided completely, because the number of buckets is limited.
  • Entries in one bucket are kept in a linked list.
  • Since Java 8: when a bucket holds more than 8 entries and the table has at least 64 buckets, the list is converted to a Red-Black Tree, so lookup improves from O(n) to O(log n). When the bucket drops below 6 entries, it reverts to a list. A good hashCode() keeps collisions rare.

equals() and hashCode() must be consistent

  • Hash-based collections (HashMap, HashSet, Hashtable) use hashCode() to choose the bucket, and equals() to find the exact object in it.
  • If two objects are equal by equals(), they must return the same hashCode(). Otherwise duplicates can be stored, or existing objects cannot be found.

ConcurrentHashMap

  • Thread-safe, and provides the same operations as HashMap.
  • Reads do not lock. Writes lock only the part of the map they change, so several writers can work on different parts at the same time. The classic design (Java 7) divided the map into 16 segments by default. Newer versions (Java 8 and later) lock individual bins using compare-and-swap, which gives similar results.
  • Does not allow null keys or values.
  • Its iterators are weakly consistent (fail-safe): they do not throw ConcurrentModificationException when the map is modified during iteration, and may or may not show the latest updates.

8.16 Arrays.asList() vs List.of()

List<String> list1 = Arrays.asList("A", "B", "C");
list1.set(1, "X");   // allowed: fixed-size list backed by the array
list1.add("D");      // UnsupportedOperationException

List<String> list2 = List.of("A", "B", "C");   // Java 9+
list2.set(1, "X");   // UnsupportedOperationException: fully immutable
  • Arrays.asList(): fixed size. Elements can be updated with set(), but not added or removed.
  • List.of() (Java 9+): fully immutable. No add, remove or update.
  • Use Arrays.asList() when updates are needed but resizing is not. Use List.of() for immutability and safety.

8.17 HashMap vs Hashtable vs ConcurrentHashMap (Summary)

  • HashMap: not synchronized, allows null keys and values, fast in single-threaded code. Package java.util.
  • Hashtable: synchronized (thread-safe, but slower), no null keys or values.
  • ConcurrentHashMap: thread-safe with better concurrency. Locks only part of the map, not the whole map. No null keys or values. Package java.util.concurrent.
  • HashMap is not thread-safe. For concurrent use, prefer ConcurrentHashMap, or Collections.synchronizedMap() as a safer option.
  • Overriding equals() without hashCode() breaks map lookups. Equal objects can get different hash codes. Override both when a custom object is used as a key.

10. Java Design Patterns

Design patterns are typical, reusable solutions to common design problems. Each pattern is a blueprint that can be adapted to the code at hand.

10.1 Creational Patterns

Factory Method

  • A superclass or interface defines how to create an object, and subclasses or a factory class decide which concrete class to instantiate.
  • The client works only with the common interface, so code does not depend on the concrete classes. Replace direct new calls with calls to a factory method.
  • Use case: dynamic implementation loading. For example, a PaymentFactory returns a CreditCardPaymentProcessor or a PayPalPaymentProcessor depending on the user's choice. 
public interface Shape { void draw(); }
public class Rectangle implements Shape { public void draw() { System.out.println("Inside Rectangle::draw() method."); } }
public class Square implements Shape    { public void draw() { System.out.println("Inside Square::draw() method."); } }

public class ShapeFactory {
    public Shape getShape(String shapeType) {
        if (shapeType == null) return null;
        if (shapeType.equalsIgnoreCase("RECTANGLE")) return new Rectangle();
        if (shapeType.equalsIgnoreCase("SQUARE")) return new Square();
        return null;
    }
}

Shape shape = new ShapeFactory().getShape("RECTANGLE");
shape.draw();   // Inside Rectangle::draw() method.

Abstract Factory

  • Produces families of related objects without naming their concrete classes. It is one level above the Factory pattern, because it returns factories.
  • Advantages: isolates client code from concrete classes, makes it easy to exchange object families, and keeps objects consistent.
  • Example: an AbstractFactory with getBank(String) and getLoan(String). BankFactory returns HDFC or SBI banks, and LoanFactory returns HomeLoan or EducationLoan. A FactoryCreator.getFactory("Bank") method chooses the factory.

Builder

  • Constructs a complex object step by step. The same construction code can produce different representations of the object.
  • Advantages: separates construction from representation, gives better control over construction, and allows the internal representation to change.
  • Example: a CivilEngineer (the director) calls buildBasement(), buildStructure(), buildRoof() and buildInterior() on a HouseBuilder. IglooHouseBuilder and TipiHouseBuilder each build a different House, and getHouse() returns the result.
  • Practical use: immutable DTOs or entities with many fields. Libraries such as Lombok provide @Builder.

Prototype

  • Creates a new object by copying an existing one, instead of creating it from scratch. The copy can be customized.
  • Example: a Prototype interface with getClone(), implemented by an EmployeeRecord class. getClone() returns a new EmployeeRecord with the same field values.

Singleton

Ensures a class has only one instance, with a global access point. Useful for a shared resource such as a database connection, which would be costly to create for every object.

To build a singleton: a private static instance, a private constructor, and a public static factory method (getInstance()).

  • Eager initialization: the instance is created when the class is loaded. 
    public class GFG {
    private static final GFG instance = new GFG();
    private GFG() { }
    public static GFG getInstance() { return instance; }
}
  • Lazy initialization: the instance is created the first time it is needed. 
    public class GFG {
    private static GFG instance;
    private GFG() { }
    public static GFG getInstance() {
        if (instance == null) instance = new GFG();
        return instance;
    }
}
  • Thread-safe lazy initialization: make getInstance() synchronized, so two threads cannot create two instances at the same time. 
    public static synchronized GFG getInstance() {
    if (instance == null) instance = new GFG();
    return instance;
}

10.2 Structural Patterns

Adapter (also called Wrapper)

Converts the interface of a class into the interface that a client expects. It lets two incompatible classes work together and reuses existing functionality.

public interface MediaPlayer   { void play(String filename); }
public interface MediaPackage  { void playFile(String filename); }

public class MP3 implements MediaPlayer {
    public void play(String filename) { System.out.println("Playing MP3 File " + filename); }
}
public class MP4 implements MediaPackage {
    public void playFile(String filename) { System.out.println("Playing MP4 File " + filename); }
}
public class VLC implements MediaPackage {
    public void playFile(String filename) { System.out.println("Playing VLC File " + filename); }
}

// Adapter: makes a MediaPackage look like a MediaPlayer
public class FormatAdapter implements MediaPlayer {
    private MediaPackage media;
    public FormatAdapter(MediaPackage m) { media = m; }
    public void play(String filename) {
        System.out.print("Using Adapter --> ");
        media.playFile(filename);
    }
}

// Usage
MediaPlayer player = new MP3();
player.play("file.mp3");
player = new FormatAdapter(new MP4());
player.play("file.mp4");
player = new FormatAdapter(new VLC());
player.play("file.avi");

Bridge

Decouples an abstraction from its implementation, so that the two can vary independently. Both can be extended without affecting the other.

  • Advantages: separates implementation from the interface, improves extensibility, and hides implementation details from the client.
  • Structure:
    • DrawAPI is the implementor interface: drawCircle(int radius, int x, int y).
    • RedCircle and GreenCircle are concrete implementors.
    • Shape is an abstract class that holds a DrawAPI reference and declares draw(). 
// Concrete abstraction: Circle uses a DrawAPI
public class Circle extends Shape {
    private int x, y, radius;
    public Circle(int x, int y, int radius, DrawAPI drawAPI) { super(drawAPI); this.x = x; this.y = y; this.radius = radius; }
    public void draw() { drawAPI.drawCircle(radius, x, y); }
}

Shape redCircle = new Circle(100, 100, 10, new RedCircle());
Shape greenCircle = new Circle(100, 100, 10, new GreenCircle());
redCircle.draw();    // Drawing Circle[ color: red, radius: 10, x: 100, 100]
greenCircle.draw();  // Drawing Circle[ color: green, radius: 10, x: 100, 100]

Composite

  • Treats a group of objects in the same way as a single object. Objects are arranged in a tree that represents both part and whole.
  • A class holds a group of its own objects and provides methods to add or remove them.
  • Advantages: defines class hierarchies of primitive and complex objects, makes it easy to add new kinds of components, and gives flexible structures.
  • Example: an Employee class with a list of subordinates. CEO has headSales and headMarketing, and each of them has their own employees. Printing the CEO and then iterating over getSubordinates() prints the whole organization.

Decorator

  • Attaches extra responsibilities to an object dynamically, using composition instead of inheritance.
  • Advantages: more flexible than static inheritance, extends behavior by adding new classes, and avoids putting all behavior in one class.
  • Structure: a Shape interface, concrete shapes (Rectangle, Circle), an abstract ShapeDecorator that holds a Shape, and a concrete decorator such as RedShapeDecorator that adds a red border. 
    Shape circle = new Circle();
Shape redCircle = new RedShapeDecorator(new Circle());
circle.draw();     // Shape: Circle
redCircle.draw();  // Shape: Circle, then Border Color: Red

Facade

  • Provides a simplified interface to a library, framework or a complex set of classes. One class exposes simple methods and delegates the calls to the subsystem.
  • Advantages: shields clients from subsystem complexity, and reduces coupling between subsystems and clients.
  • Example: ShapeMaker creates Circle, Rectangle and Square internally, and offers drawCircle(), drawRectangle() and drawSquare().

Flyweight

  • Reuses existing objects with the same state instead of creating new ones. It shares the common (intrinsic) part of state between objects to reduce memory and object count.
  • Advantages: fewer objects, less memory, and less storage if the objects are persisted.
  • Example: a ShapeFactory keeps a HashMap of Circle objects keyed by colour. getCircle("Red") returns the cached circle, or creates and caches one if none exists. Twenty random draws create only as many circles as there are distinct colours.

Proxy (also called Surrogate or Placeholder)

  • A proxy is an object that stands in for another object. It controls access to the original, and can do work before or after the request reaches it.
  • Advantage: protects the original object from the outside world, and can delay expensive work.
  • Example: ProxyImage implements Image and creates the RealImage (which loads the file from disk) only when display() is first called. 
    Image image = new ProxyImage("test_10mb.jpg");
image.display();   // Loading test_10mb.jpg, then Displaying test_10mb.jpg
image.display();   // Displaying test_10mb.jpg (already loaded)

10.3 Behavioral Patterns

Behavioral patterns deal with how objects interact and share responsibilities. Objects should communicate while staying loosely coupled, so the implementation and the client are not hard-coded to each other.

Chain of Responsibility

  • A request is passed along a chain of handlers. Each handler either processes the request or passes it to the next handler.
  • Use it for: decoupling the sender of a request from its receiver, and choosing the processing strategy at run time.
  • Java example: Servlet filters. Each Filter.doFilter() processes the request and then calls chain.doFilter(...) to pass control to the next filter. 
    public class CustomFilter implements Filter {
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        // process the request
        chain.doFilter(request, response);
    }
}

Command

  • A request is wrapped in a command object and passed to an invoker. The invoker finds the object that can execute it, and that object performs the action.
  • Advantages: separates the object that triggers an operation from the object that performs it, and makes it easy to add new commands without changing existing classes.
  • Example: an Order interface with execute(), implemented by BuyStock and SellStock. Both wrap a Stock receiver. A Broker collects orders with takeOrder() and runs them all with placeOrders(). 
    Stock abcStock = new Stock();
Broker broker = new Broker();
broker.takeOrder(new BuyStock(abcStock));
broker.takeOrder(new SellStock(abcStock));
broker.placeOrders();   // Stock [ Name: ABC, Quantity: 10 ] bought, then ... sold

Interpreter

  • Evaluates a language grammar or expression. It defines an expression interface, and implementations that interpret a given context.
  • Used in: SQL parsing and symbol-processing engines.
  • Example in the source: a Pattern interface with conversion(String), implemented by InfixToPostfixPattern, which converts an infix expression to postfix. For a+b*c, the output is abc*+.

Iterator

  • Traverses the elements of a collection without exposing its internal structure (list, stack, tree and so on). Also called *Cursor*.
  • Advantages: supports different ways of traversing a collection, and simplifies the collection's interface.
  • Structure: an Iterator interface with hasNext() and next(), a Container interface with getIterator(), and a NameRepository that returns a private inner NameIterator.
  • Note: this is the same idea as Java's built-in java.util.Iterator.

Mediator

  • Reduces the communication complexity between many objects. A mediator class handles all communication, so the objects stay loosely coupled.
  • Used in: message-based systems such as chat applications, and wherever many objects communicate in complex but well-defined ways.
  • Example: a ChatRoom.showMessage(user, message) method. Each User.sendMessage() passes its message through the ChatRoom, so users never reference each other directly.

Memento

  • Saves and restores the previous state of an object without exposing how it is implemented. Also called a snapshot.
  • Benefits: preserves encapsulation, and simplifies the originator.
  • Used in: undo and redo operations, and database transactions.
  • Structure:
    • Memento holds the saved state.
    • Originator creates a memento with saveStateToMemento() and restores from one with getStateFromMemento().
    • CareTaker keeps the list of mementos. 
originator.setState("State #1");
originator.setState("State #2");
careTaker.add(originator.saveStateToMemento());
originator.setState("State #3");
careTaker.add(originator.saveStateToMemento());
originator.setState("State #4");
originator.getStateFromMemento(careTaker.get(0));   // State #2
originator.getStateFromMemento(careTaker.get(1));   // State #3

State

  • Lets an object change its behavior when its internal state changes. It looks as if the object changed its class.
  • Benefits: keeps state-specific behavior in separate classes, and makes state transitions explicit.
  • Use it when: an object's behavior depends on its state and must change at run time, or when operations contain large conditional statements that depend on the state.
  • Structure: a State interface with doAction(Context). StartState and StopState implement it, and each calls context.setState(this). The Context holds the current state. 
    Context context = new Context();
new StartState().doAction(context);   // Player is in start state
new StopState().doAction(context);    // Player is in stop state

Strategy (also called Policy)

  • Several algorithms exist for one task, and the client chooses which one to use, at run time.
  • Benefits: a substitute for subclassing. Each behavior lives in its own class, which removes conditional statements, and new behavior can be added without changing the application.
  • Used when: several classes differ only in their behavior (for example, the Servlet API).
  • Example: a Strategy interface with doOperation(int, int), implemented by OperationAdd, OperationSubstract and OperationMultiply. A Context object is given a strategy. 
    Context context = new Context(new OperationAdd());
context.executeStrategy(10, 5);       // 15
context = new Context(new OperationMultiply());
context.executeStrategy(10, 5);       // 50

Observer

  • A one-to-many relationship: when one object (the subject) changes, all dependent objects (observers) are notified automatically.
  • Defines a subscription mechanism for notifying several objects about events in the observed object.
  • Benefits: describes loose coupling between subject and observers, and supports broadcast communication.
  • Structure:
    • Subject keeps a list of observers, has attach(observer), and calls notifyAllObservers() in setState().
    • Observer is an abstract class with update(). BinaryObserver, OctalObserver and HexaObserver each print the subject's state in their own format. 
Subject subject = new Subject();
new HexaObserver(subject);
new OctalObserver(subject);
new BinaryObserver(subject);
subject.setState(15);   // Hex String: F, Octal String: 17, Binary String: 1111
subject.setState(10);   // Hex String: A, Octal String: 12, Binary String: 1010
  • Java examples: Swing and AWT event listeners.

Template Method

  • The superclass defines the skeleton of an algorithm in a final template method. Subclasses override specific steps, without changing the structure of the algorithm.
  • Benefit: reuses code and avoids duplication of the common behavior.
  • Example: Game has the final method play(), which calls initialize(), startPlay() and endPlay(). Cricket and Football override the three steps. 
    Game game = new Cricket();
game.play();   // Cricket Game Initialized! ... Cricket Game Finished!

Visitor

  • Performs an operation on a group of similar objects. The operation is moved out of the objects into a separate visitor class, so an algorithm can change without changing the element classes.
  • Structure:
    • ComputerPart (element) has accept(visitor). Keyboard, Mouse and Monitor implement it.
    • Computer is a composite element that holds the parts. Its accept() visits each part and then itself.
    • ComputerPartVisitor declares a visit() method for each element type. ComputerPartDisplayVisitor implements them. 
ComputerPart computer = new Computer();
computer.accept(new ComputerPartDisplayVisitor());
// Displaying Mouse. Displaying Keyboard. Displaying Monitor. Displaying Computer.

10.4 Design Pattern Interview Points

  • Advantages of design patterns: they are reusable across projects, help define system architecture, capture experience from expert developers, and make the design of an application more transparent.
  • Factory pattern: the most used pattern in Java. The creation logic is hidden from the client, and subclasses choose which object to create. Also called a *virtual constructor*.
  • Abstract Factory: an interface or abstract class creates families of related objects without naming their concrete classes. It is one level above the Factory pattern.
  • Structural patterns: rely on inheritance and interfaces to make classes and objects work together as one structure.
  • Singleton:
    • Ensures only one instance exists, with a global access point. java.lang.Runtime is an example.
    • Two forms: early instantiation (created at load time) and lazy instantiation (created when first needed).
    • Thread-safe options: double-checked locking, a static instance initialized at class loading, or an enum singleton, which is the simplest.
    • A singleton can be cloned unless clone() is blocked. Override clone() to throw an exception, or use an enum.
  • Adapter: converts one interface into another, so a class can be used through a different interface. Also called a *wrapper*.
  • Decorator: adds behavior at run time with composition instead of inheritance. Used heavily in java.io: BufferedReader and BufferedWriter are examples.
  • Strategy vs State: their UML diagrams look the same. State manages the state of an object, and changes behavior as the state changes. Strategy describes a set of interchangeable algorithms that the client picks.
  • Composite advantages: clients treat single objects and groups the same way. Adding new component types is easy, and the structure is flexible.
  • Patterns used in the JDK:
    • Decorator: wrapper classes and java.io streams.
    • Singleton: Runtime.
    • Factory: Integer.valueOf().
    • Observer: Swing and AWT event handling.
  • Builder advantages: clear separation between construction and representation. Fewer constructor parameters, and readable method calls. Objects are always created in a complete state. Immutable objects are easy to build.
  • Proxy: a placeholder that controls access to the real object. It can add security (hiding the original's details), and supports on-demand loading. Also called a *surrogate*.
  • Bridge vs Adapter: Adapter makes the interfaces of one or more classes look similar. Bridge separates a class's interface from its implementation, so the implementation can change without changing the client code.

12. Generics and JDBC

12.1 Generics

  • Generics were introduced in J2SE 5 to provide type-safe collections and classes.
  • Without generics, a collection could hold any type of object, and each retrieved item had to be cast.
  • Syntax: ClassOrInterface<Type>, for example ArrayList<String>.

Benefits:

  1. Stronger type checks at compile time.
  2. No casting required when retrieving elements.
  3. Type safety: only one type of object can be stored.

13. Java 17 and Java 21 Features

13.1 Java 17

  • Sealed classes and interfaces: restrict which classes or interfaces may extend or implement them. Declared with sealed and a permits clause. 
    public sealed class Shape permits Circle, Square, Rectangle {
    // common properties and methods
}
  • Pattern matching for switch: matches patterns for Strings, enums and records in case labels. Adds *guarded* patterns (pattern && boolean expression) and *parenthesized* patterns. The arrow (->) indicates the code to run on a match. (Finalized in Java 21.)
  • Enhanced pseudo-random number generators: a new interface type and implementations for PRNG algorithms, with better support for stream-based operations.
  • Strongly encapsulated JDK internals: non-critical internal JDK elements are strongly encapsulated.
  • Foreign Function and Memory API: lets Java programs access code and data outside the JVM.
  • Vector API: expresses vector computations that compile to optimal vector instructions at run time.
